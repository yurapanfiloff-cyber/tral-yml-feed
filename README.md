# Автоматический YML-фид для tral-diler.ru

Генератор получает только товары из блока «Модели полуприцепов и тралов» на странице:

`https://tral-diler.ru/traly-i-polupricepy-v-nalichii`

Он автоматически находит идентификаторы блока Tilda, обходит все страницы списка, открывает каждую карточку и формирует YML для Яндекс Директа.

## Что берётся в фид

- список URL — только из указанного товарного блока;
- название — H1 отдельной карточки;
- цена и галерея — из данных товара Tilda, связанных с карточкой;
- категория — из хлебных крошек карточки;
- бренд и модель — из характеристик карточки и данных товара;
- технические параметры — из таблиц характеристик карточки и кратких характеристик товара;
- ID — последний URL-слаг карточки, например `amur-lyr9600js`.

Для товаров с подтверждённым заводским индексом используется комбинированный офер: `name`, `typePrefix`, `vendor` и `model`.

Если заводской индекс модели не подтверждён, генератор не придумывает `<model>` и формирует упрощённый офер без атрибута `type="vendor.model"`. В `<name>` объединяются тип техники, бренд и основные характеристики: количество осей, грузоподъёмность и длина площадки или габариты.

Товары без числовой цены в YML не включаются. Их URL, название и причина исключения сохраняются в `audit.json`. Остальные корректные товары продолжают публиковаться.

## Защита публикации

Рабочий `direct.xml` заменяется только после полного успешного цикла. До замены проверяется:

1. число полученных товаров совпадает с числом, которое сообщает Tilda;
2. число подготовленных к публикации товаров не ниже `minimum_products`;
3. количество новых оферов не упало относительно рабочего фида больше, чем разрешено в `max_count_drop_percent`;
4. все карточки вернули HTTP 200;
5. у публикуемых товаров есть цена, изображение, название, категория и бренд;
6. ID непустые и уникальные;
7. XML разбирается без ошибок, содержит все оферы и обязательные поля;
8. временный файл повторно читается и проверяется перед атомарной заменой.

Уменьшение до порога включительно публикуется с предупреждением. Если уменьшение превышает порог, предыдущий рабочий фид сохраняется. Для ручного подтверждения проверенной публикации используется параметр `--force-publish`.

При критической ошибке предыдущий рабочий фид остаётся без изменений. Подробности записываются в `audit.json`, краткий статус — в `status.json`, история запусков — в журнал. После успешного обновления прежняя версия сохраняется рядом как `direct.xml.previous`.

## Основной вариант: GitHub Actions и GitHub Pages

В этой конфигурации отдельный сервер не требуется:

- GitHub Actions запускает генератор один раз в сутки;
- предыдущий рабочий `direct.xml` загружается перед новым запуском для контроля уменьшения;
- последняя проверенная версия сохраняется также в репозитории как резерв для следующего запуска;
- новый пакет GitHub Pages развёртывается только после успешной генерации и всех проверок;
- при ошибке публикация не выполняется, поэтому прежний рабочий фид остаётся доступным;
- отчёты `audit.json`, `status.json` и журнал запуска сохраняются как артефакт GitHub Actions на 30 дней;
- ручное подтверждение критического уменьшения выполняется через запуск workflow с параметром `force_publish`.

Рабочий адрес после настройки Pages и DNS:

`https://feed.tral-diler.ru/direct.xml`

Файл `direct.yml` также публикуется как резервная копия. Основным адресом является
`direct.xml`: GitHub Pages корректно передаёт для него тип XML и кодировку UTF-8.

### Первоначальная настройка GitHub

1. Создать публичный репозиторий и загрузить в него содержимое проекта. На бесплатном тарифе GitHub Pages работает для публичного репозитория.
2. В `Settings → Pages → Build and deployment` выбрать источник `GitHub Actions`.
3. В `Settings → Pages → Custom domain` указать `feed.tral-diler.ru`.
4. В DNS Tilda создать запись `CNAME` с хостом `feed` и значением, которое покажет GitHub Pages.
5. В разделе `Actions` вручную запустить workflow `Generate YML feed`.
6. После успешного выпуска HTTPS включить `Enforce HTTPS`.

Расписание находится в `.github/workflows/generate-feed.yml`: запуск ежедневно в 02:17 UTC, то есть в 05:17 по московскому времени. GitHub может запускать задания с задержкой, поэтому минута выбрана не в начале часа.

После ручного изменения цен или ассортимента Роман может сразу запустить обновление через `Actions → Generate YML feed → Run workflow`. Если этого не сделать, изменения автоматически попадут в фид при ближайшем ежедневном запуске.

### Ручная публикация при уменьшении более чем на 20%

Откройте `Actions → Generate YML feed → Run workflow`, включите параметр ручного подтверждения и запустите workflow. Параметр передаётся генератору как `--force-publish` и обходит только блокировку критического уменьшения количества оферов. Остальные критические проверки продолжают действовать.

### Поведение при ошибке

Если генератор завершился с ошибкой, шаг развёртывания GitHub Pages не выполняется. Опубликованный ранее фид остаётся без изменений. Отчёт неудачного запуска можно скачать внизу страницы соответствующего запуска Actions в блоке `Artifacts`.

## Альтернативный вариант: отдельный VPS

- Linux-сервер с постоянным доступом в интернет;
- Python 3.10 или новее;
- Nginx;
- HTTPS-сертификат для `feed.tral-diler.ru`;
- DNS-запись `feed.tral-diler.ru`, направленная на сервер.

На Tilda нельзя разместить исполняемый скрипт и настроить системное расписание. Поэтому генератор работает либо через GitHub Actions, либо на отдельном сервере или хостинге с Python и заданием по расписанию.

## Установка на VPS

Команды выполняются от пользователя с правами администратора.

```bash
useradd --system --home /opt/tral-yml-feed --shell /usr/sbin/nologin tralfeed
mkdir -p /opt/tral-yml-feed /etc/tral-yml-feed \
  /var/lib/tral-yml-feed /var/log/tral-yml-feed \
  /var/www/feed.tral-diler.ru/public
cp feed_generator.py requirements.txt /opt/tral-yml-feed/
cp config.example.json /etc/tral-yml-feed/config.json
python3 -m venv /opt/tral-yml-feed/.venv
/opt/tral-yml-feed/.venv/bin/pip install -r /opt/tral-yml-feed/requirements.txt
chown -R tralfeed:tralfeed /opt/tral-yml-feed /var/lib/tral-yml-feed \
  /var/log/tral-yml-feed /var/www/feed.tral-diler.ru/public
```

Проверьте пути и параметры в `/etc/tral-yml-feed/config.json`.

## Первый аудит

Первый запуск лучше сделать без публикации:

```bash
sudo -u tralfeed /opt/tral-yml-feed/.venv/bin/python \
  /opt/tral-yml-feed/feed_generator.py \
  --config /etc/tral-yml-feed/config.json \
  --audit-only
```

Результат находится в `/var/lib/tral-yml-feed/audit.json`. Отсутствие цены фиксируется как исключение товара, отсутствие модели — как переход на упрощённый офер. Код 1 возвращается только при критической ошибке, которая блокирует публикацию.

## Ручная публикация

Обычная публикация:

```bash
sudo -u tralfeed /opt/tral-yml-feed/.venv/bin/python \
  /opt/tral-yml-feed/feed_generator.py \
  --config /etc/tral-yml-feed/config.json
```

Если генератор остановил обновление из-за уменьшения фида более чем на 20%, сначала проверьте отчёт. Для осознанного ручного подтверждения используйте:

```bash
sudo -u tralfeed /opt/tral-yml-feed/.venv/bin/python \
  /opt/tral-yml-feed/feed_generator.py \
  --config /etc/tral-yml-feed/config.json \
  --force-publish
```

## Ежедневный запуск на VPS

```bash
cp tral-yml-feed.service tral-yml-feed.timer /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now tral-yml-feed.timer
systemctl list-timers tral-yml-feed.timer
```

Время запуска: ежедневно в 05:17 по часовому поясу сервера, плюс случайная задержка до пяти минут. Пропущенный из-за перезагрузки запуск выполняется после старта сервера.

## Постоянный HTTPS-адрес на VPS

Рекомендуемый адрес:

`https://feed.tral-diler.ru/direct.xml`

Перед подключением конфигурации Nginx нужно:

1. создать DNS-запись для `feed.tral-diler.ru`;
2. получить сертификат Let's Encrypt;
3. проверить пути сертификата в `nginx-feed.conf`;
4. подключить файл в Nginx и проверить конфигурацию.

```bash
cp nginx-feed.conf /etc/nginx/sites-available/feed.tral-diler.ru
ln -s /etc/nginx/sites-available/feed.tral-diler.ru /etc/nginx/sites-enabled/feed.tral-diler.ru
nginx -t
systemctl reload nginx
```

После первой успешной публикации проверьте:

```bash
curl -I https://feed.tral-diler.ru/direct.xml
curl -fsS https://feed.tral-diler.ru/direct.xml | xmllint --noout -
```

## Диагностика

```bash
systemctl status tral-yml-feed.service
journalctl -u tral-yml-feed.service -n 100 --no-pager
tail -n 100 /var/log/tral-yml-feed/generator.log
cat /var/lib/tral-yml-feed/status.json
```

Код возврата `0` означает успешную проверку или публикацию, `1` — обнаружена ожидаемая ошибка данных, `2` — непредвиденная техническая ошибка.
